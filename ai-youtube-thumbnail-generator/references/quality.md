# Thumbnail acceptance

Open the final delivered image, not just a model description or receipt. Inspect
at full size and at 168×94. If needed, place the small preview against both white
and dark backgrounds; no numerical contrast or model score replaces looking.

| Gate | Pass condition |
| --- | --- |
| Promise | The scene adds a truthful question, emotion or outcome to the title; no unsupported claims, metrics or fake product functions. |
| Focal point | One subject or clearly grouped comparison is identifiable in one glance; background and props do not compete. |
| Overlay | Exact supplied text, correct language and spelling, readable without zooming, short enough for the feed. |
| Hierarchy | Title-sized text and subject have clean separation; no accidental caption, logo, tiny UI text or watermark. |
| Geometry | Required product shape, relevant before/after identity and supplied likeness are retained; note that generic smoke tests cannot validate real references. |
| Safe area | Bottom-right 18% of width × 15% of height contains no essential copy or subject detail; margins survive export. |
| Technical | Actual delivered JPEG is 1280×720, below 2,000,000 bytes and decodes; inspect any model-preset crop. |

Report each failed gate specifically. Fix the most important failure with a
single edit or a simpler concept rather than paying for an unconstrained batch.
Keep candidates versioned so failures are visible. Limit text repairs to bounded
model edits or a shorter/no-text option; do not hide defects through an
unreported text patch. Crop/resize/compression are delivery operations, not proof
that a missing visual element was fixed.

Treat “works” as three separate claims:

- **Executable:** a saved prompt reached an actual image backend and returned an
  image. Keep its receipt, actual model and dimensions.
- **Usable image:** technical checks and human/agent visual inspection passed
  for that example. It does not mean every future subject or language will pass.
- **Effective on YouTube:** requires actual channel test evidence. Repository
  stars, an attractive render, CLIP similarity, facial expression heuristics and
  model critiques do not establish CTR lift or audience retention.

For an A/B comparison, identify the one intended variable, preserve all others
as far as the backend allows, then check for incidental image changes. Use the
channel's native test results and relevant watch-time/retention context. Do not
invent universal CTR benchmarks, sample sizes, winners or statistical confidence.
