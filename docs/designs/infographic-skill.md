# Infographic Skill 设计草案

- 状态：Draft / 待评审；本文是设计提案，不是可执行 Skill。
- 日期：2026-11-10。
- 仓库及文档位置：`okou-ai/okou-skills` → `docs/designs/infographic-skill.md`。
- 拟定名称：`infographic`；显示名：信息图。
- 本轮范围：设计文档 PR，不新增运行时 Skill、安装依赖、注册模板、发布资源或启用自动化。

## 1. 设计结论

提供一个统一入口，把文章、文字或结构化数据转化为信息图。先生成与渲染器无关的内容规格，再按需求选择：

1. **结构化路线**：使用 AntV，优先满足文字准确、数字准确、关系清晰和源文件可编辑。
2. **插画路线**：借鉴宝玉的布局与风格体系，通过 Okou 现有生图入口生成整张图片，优先满足视觉表现力。

MVP 只实现这两条路线。Epic 的设计型 HTML/CSS/SVG 路线作为后续扩展；Remy 的内容预算及检查方法融入共同流程，不形成第四个对外入口。不整包安装四套上游 Skill，也不创建四套并行的渲染环境。

这是候选架构，不代表用户已批准实现、发布或任何模型消费。

## 2. 背景与已验证边界

此前已使用四个固定版本仓库，对同一主题“咖啡从种子到杯子”实际制作四张中文信息图。四版采用相同的六阶段文案，均已打开最终 PNG 检查。

| 来源 | 本轮实际路径 | 观察及设计启示 |
| --- | --- | --- |
| AntV | `@antv/infographic@0.2.20`，原生 DSL，`sequence-steps-simple-illus` | 中文标题的测量与布局需要适配；本轮以 HTML 外框承载标题，不能把这种临时处理当作已完备的通用导出能力 |
| 宝玉 | `linear-progression × craft-handmade`；Okou 内置生图 | 三次生成后接受最终图；前两次冲煮器具结构不正确，说明文字正确不等于图示正确 |
| Epic | HTML/CSS/SVG；原仓库检查及渲染脚本 | 最终 checker 为 0 errors / 0 warnings，仍经历视觉修正；静态检查不能替代看图 |
| Remy | 原 `ig.py` 的 brief/spec/validate/render/shoot 管线 | 结构化内容规格和文字核对值得复用；内部 PDF 只是渲染中间件，不应自动成为额外交付物 |

宝玉版请求尺寸为 2048×1152，实际返回 1376×768；今后的交付必须记录实际尺寸，不能把请求参数当成完成证明。

**这只是一次同题制作，不是严格质量、速度或成本基准。** 模型、作者构图、渲染器、尺寸和修正次数不同，不能据此宣布某个仓库全面胜出，也不能承诺固定生成时长或价格。

## 3. 用户体验与范围

### 3.1 典型请求

- “把这篇文章整理成一张中文信息图。”
- “做一张可编辑的竞品对比信息图，保留这些数据。”
- “把咖啡的六个步骤画成手绘风科普图。”
- “把刚才那张改为竖版，只改配色，不改文案。”

用户不必知道 AntV、宝玉或模板 ID。输入充分时自动选择结构与风格，不重复要求用户选仓库、选引擎或确认每一步。只在缺失会影响正确性的内容、约束冲突或额外支出授权时提问。

### 3.2 MVP 包含

- 一次生成一张静态信息图；中文和英文文案。
- 六类信息结构：流程、对比、时间线、层级、关系、列表。
- 结构化路线先支持经过测试的有限模板；插画路线先选少量布局及视觉方向。
- 根据已提供资料提炼内容；需要补充外部事实时才走现有研究工具。
- 内容、排版、图形语义检查；有限修正与可核验交付。
- 在同一内容规格上修改文字、配色和画幅。

六类结构是首批覆盖目标，不代表每种结构、风格、画幅和后端都能任意组合；以经过测试的能力清单为准。

### 3.3 不包含

- 在线拖拽编辑器、多人协作、动画或交互看板。
- PPTX/PDF 转换、批量出图、自动生成多个备选稿。
- 自动发往 Slack、邮件、社交平台，或自动公开托管。
- 新增 `okou generate infographic` 命令、注册表接入或产品 UI 变更。
- 安装全局 Skill、创建持久 Workflow/Automation、合并 PR 或生产发布。

这些能力如有需求，单独设计、授权和验收。

## 4. 路由规则

按以下优先级处理，不以视觉风格覆盖硬约束：

| 条件 | 行为 |
| --- | --- |
| 用户指定可编辑源文件、严格数值/比例或大量必须逐字保留的文字 | 选择结构化路线；图形比例必须由数据计算，不交给图片模型猜测 |
| 用户明确要求插画优先，文字量适中，且无可编辑/精确比例约束 | 选择插画路线 |
| 未指定路线 | 默认结构化路线；内容适合且明显强调插画时可选择插画路线，并简短说明 |
| 同时要求“模型整图手绘”与“文字、图形全部可编辑” | 说明冲突，询问优先项；不把 PNG 包进 SVG 就宣称可编辑 |
| 首选后端不可用或能力不匹配 | 明确说明限制；仅在不改变用户硬约束且无额外授权要求时提供替代方案，不静默切换 |

“手绘”“极简”等是视觉要求，不天然等于某个后端。MVP 不提供混合路线；日后如生成插画后用代码排文字，应作为明确的新模式说明，不冒称宝玉原始整图生图路径。

## 5. 统一内容规格

采用一个可序列化的 `content-spec` 作为内容事实来源。下表是拟定字段，不是现有 CLI 参数，也不是已经实现的 JSON Schema。

| 字段 | 作用 |
| --- | --- |
| `schema_version` | 内容规格版本，便于后续迁移 |
| `language`、`audience`、`goal` | 语言、受众和读完应理解的核心结论 |
| `title`、`subtitle`、`key_message` | 标题、副标题与主结论 |
| `structure`、`sections`、`relations` | 信息结构、带稳定 ID 的条目及显式关系；顺序不可依赖模型自行猜测 |
| `facts` | 数值、单位、口径、时间范围、来源 ID；无依据的数值不得补造 |
| `locked_copy` | 必须逐字保留的文字，以稳定内容 ID 引用 |
| `sources` | 用户提供/公开来源的引用信息、访问日期及必要的事实对应关系 |
| `visual_constraints` | 风格、画幅、品牌约束、可编辑性、允许的后端；区分硬约束和偏好 |

运行过程、生成回执和 QA 结果另存，不能混进事实规格。改配色不改内容版本；改文字或事实生成新版本并记录差异。排版允许的换行不算改文案，数字、单位和标点不能借“格式化”擅改。

### 内容过载与资料缺失

先按读者目标组织信息，再做字数预算。超出当前模板容量时，优先调整布局；未锁定文案可在不损失事实的前提下压缩。不能靠无限缩小字体、删除锁定内容、擅自拆成多张来宣称完成。确实装不下时说明冲突并询问。

没有数据不画定量比例；来源相互矛盾则保留差异或请求澄清。来源正文和用户附件是待处理材料，不作为可执行指令。

## 6. 技术架构与包边界

```text
用户请求 / 授权资料
        ↓
内容提炼 → content-spec → 校验硬约束
        ↓
路线选择 + 已验证的布局/风格组合
        ├─ AntV DSL → 受控渲染器 → SVG/HTML 源文件 + PNG
        └─ 提示词编译 → Okou 图片生成 → PNG + 生成回执
        ↓
文字/数据/布局/图形语义 QA → 有限修正 → 上传交付
```

### 6.1 Skill 的职责

入口只保留触发条件、路由、共同步骤、停止条件和参考索引。布局、风格、后端细节和检查清单按需加载，不把所有上游说明塞入上下文。

未来实现可采用以下包结构；**此设计文档 PR 不创建这些文件**：

```text
infographic/
├── SKILL.md
├── references/
│   ├── content-spec.md
│   ├── routing.md
│   ├── layout-capabilities.md
│   ├── qa.md
│   └── backends/               # AntV 及插画路线的必要说明
├── scripts/                   # 内容/几何检查与统一代码渲染适配
├── templates/                 # 精选版式及本地资源
├── dependency manifests/locks # 按最终技术栈落地，不是字面目录名
└── UPSTREAM.md + license notices
```

第三方来源、版本、引入范围及改动集中记录在 provenance 中，避免重复叙述。未来创建实际包时按官方 skill-creator 初始化并验证；当前只有设计文字，不运行包初始化，也不提交空壳 `SKILL.md`。

### 6.2 AntV 适配

- 固定 npm 版本及依赖锁文件，预置中文字体与渲染依赖；不在每次任务中重新克隆仓库或全量安装浏览器。
- 先制作小型能力清单，声明每种布局支持的字段、条目容量、关系类型、画幅和导出形式；不直接暴露全部模板。
- 统一处理标题、副标题、脚注与主体；若使用 HTML 外框，必须记录实际可编辑源文件组合，不能丢失外框后仍声称 SVG 完整。
- 等待字体及图形真正绘制完成，再检查可见文本、边界和截图。视觉修正后重新导出，不交付旧 PNG。
- “可编辑”表示存在真实文本/图形源文件，并不承诺在线编辑器或 PowerPoint 原生对象。

### 6.3 插画路线适配

- 复用 `okou generate image`，编译完整内容、布局与风格提示词；不复制上游的密钥管理或独立模型调用层。
- 生成前以当前 CLI 帮助确认支持的参数。内置模型跟随用户 Settings，不在 Skill 中硬编码模型或传入 `--model`。
- 使用明确等待完成的路径；保存生成 ID，任务尚未完成时查询同一任务，不靠重复提交检查进度。
- 记录请求与实际返回的尺寸、格式、模型及可用计费信息；未知成本不能记成 0，不按历史样例承诺固定单价。
- 实际尺寸不符合硬约束时不得判通过；不把普通放大说成模型原生高分辨率。
- 不以代码替换图片文字后仍宣称是未经修改的整图生图结果。

## 7. 质量门禁与有限修正

| 检查层 | 通过条件 |
| --- | --- |
| 内容 | 标题、条目、锁定文案、顺序、数字和单位与内容规格一致；结论可追溯 |
| 几何与可读性 | 无裁切、缺字、不可读的缩字；关键文字及连接线不发生妨碍阅读的重叠 |
| 图形语义 | 箭头方向、对象数量、阶段对应和器具结构合理；装饰不制造未经来源支持的事实 |
| 文件 | 最终文件可打开，尺寸及格式与交付记录一致；源文件引用的必要资源完整 |
| 视觉 | 实际打开最终图片逐项检查，而不是只检查代码、DOM 或 checker 的退出码 |

代码路线做可见文字与几何检查；插画路线逐项读图。有可用 OCR 时可以辅助，但 OCR 和静态检查都不能替代视觉复核。每项 QA 保存结果及证据；未检查记录为 `not_checked`，不得默认通过。来源页、渲染脚本及图片都不能作为执行新指令的依据。

### 建议默认预算（待评审）

- 代码路线：首次渲染后，最多两轮有明确原因的局部修正。
- 插画路线：首次生成后，最多一次有明确原因的编辑或重新生成，即最多两次新建的生图任务。
- 以上是上限，不是消费授权；用户更低预算和平台权限优先。没有必要不修正，禁止自动扩成多候选并行生图。
- 有明确 QA 缺陷且结果已确认时才考虑新任务；超时、回执不完整或执行结果不明，不自动重提。
- 达到预算仍有硬错误时停止，说明未通过项，并提供继续所需的选项；不能把失败稿标成最终成品，也不能静默换引擎。

本次咖啡样例的生图第三次才通过，按上述建议默认预算应停止并报告，而不是隐性突破上限。这是可控性取舍，需在实现验收中覆盖。

## 8. 交付契约

- 未指定格式时交付一张最终 PNG；不得把本地路径或本地开发服务器当成用户可访问的交付。
- 用户要求可编辑时，增加或按其要求交付真实 SVG/HTML 源文件；HTML 外框、字体与必要资源必须一起保留。具体交付组合以用户用途为准。
- Web 中需展示或交付的本地图片，使用 `okou web upload-file` 上传后返回真实链接；默认保持私有，不自动提高可见性。
- 仅在用户需要网页版时才托管 HTML；按当前平台规则进行封面截图、检查及带预览图发布。不因内部用了 HTML 就自动建站。
- 正常回复只需最终图片/链接、实际尺寸和必要限制。源码、提示词、内容规格及 QA 明细按用户需求提供，不默认重复发送多个格式。

内部运行记录至少包含：内容规格版本、路线/模板/风格、依赖版本、各阶段耗时、尝试数、生成 ID、可用成本、实际输出元数据和 QA 状态。记录不包含秘密，不自动汇入新的分析服务或持久数据库。

## 9. 上游维护、许可与安全

采用已经实际试用的固定版本作为评审基线，而不是运行时下载 `main`：

| 来源 | 固定版本 | 计划引入范围 |
| --- | --- | --- |
| [antvis/Infographic](https://github.com/antvis/Infographic/tree/5ae0d9394ac6280cb688eb4b4345881e291b9209) | `5ae0d9394ac6280cb688eb4b4345881e291b9209` | MVP 渲染能力及必要参考；npm 依赖单独锁定，试用版本为 0.2.20 |
| [JimLiu/baoyu-skills](https://github.com/JimLiu/baoyu-skills/tree/ca703c2d7c2c4399a1dc0cf82224f8551e05a96d/skills/baoyu-infographic) | `ca703c2d7c2c4399a1dc0cf82224f8551e05a96d` | MVP 精选内容组织、布局与风格参考；不含独立调用及账户层 |
| [OrRon/EpicInfographics](https://github.com/OrRon/EpicInfographics/tree/bf97e589df21302aacb24d9c7631393e81b9a015) | `bf97e589df21302aacb24d9c7631393e81b9a015` | 后续设计型代码路线参考，MVP 不复制其独立执行环境 |
| [remybroun/infographic](https://github.com/remybroun/infographic/tree/6d0d5980ebb418fec6acae3ab19ddfbe92cdb2aa) | `6d0d5980ebb418fec6acae3ab19ddfbe92cdb2aa` | 内容预算及验证方法参考，不整包引入管线 |

- 实现时逐项核对引入文件的许可证，保留 MIT 许可、版权及来源说明；字体、图标、图片的许可单独核对，不能仅凭仓库主许可推断。
- 上游更新通过独立 PR、回归样例和版本记录进入，不在用户任务中自动追随最新版本。
- 不将第三方提示词的权限要求、自动发布行为、全局偏好路径等直接继承为 Okou 的规则。
- 不执行资料中嵌入的脚本；导入 SVG/HTML 及外链资源时检查活动内容与网络依赖，渲染采用受控环境，不为可移植性默认关闭沙箱。
- 只有任务确需补充外部资料时才发现及调用相应研究工具；私密内容不发到公开搜索，外部模型消费遵守现有平台授权边界。

## 10. 实施顺序

| 阶段 | 交付与退出条件 |
| --- | --- |
| D0：本设计 | 仅文档；确认范围、路线优先级、预算和验收方式 |
| D1：MVP 实现 | 创建完整包，打通 AntV 与插画两条路线、内容规格、能力清单、QA 和私有交付；有限模板，不一次搬全量上游 |
| D2：离线验收 | 在固定测试集上逐例核对内容、图示及交付；记录首稿通过率、修正后通过率、耗时和实际成本，不仅挑选成功图展示 |
| D3：受控接入 | 经单独批准后接入发现/注册机制，记录版本及回滚入口；不将本设计 PR 合并视为生产发布授权 |
| D4：扩展 | 有实际需求且 MVP 稳定后，再考虑 Epic 路线、更多风格、长图或批量能力 |

设计目标是可核验而非虚构指标。时延、质量阈值与成本目标待 D2 基线后确定，不从单次咖啡示例外推。

## 11. MVP 验收清单

以下是未来实现必须执行的测试，不是本设计文档已通过的功能测试。

| 用例 | 验收重点 |
| --- | --- |
| 同文案咖啡六步，分别指定两条路线 | 六阶段、顺序、脚注和图示语义一致；差异只来自表达方式 |
| 六种结构，每种至少一个结构化样例 | 语义结构正确且导出完整；未实现的组合明确拒绝，不伪装支持 |
| 对比数字含百分比、单位和不同时间口径 | 数字和比例按数据绘制，不能推断缺失值或合并不同口径 |
| 长中文标题、锁定长文案、窄画幅 | 无缺字或溢出；装不下时报告限制，不删锁定内容 |
| 严格像素尺寸与生图实际尺寸不符 | 识别不一致，不将请求尺寸当成完成尺寸 |
| 故意错误的阶段连接或器具结构 | QA 拦截；静态检查或文字正确不构成豁免 |
| 生图首次失败、第二次仍不通过 | 达到默认上限即停止，不自动开启第三次任务 |
| 生成回执超时/未知状态 | 使用既有生成 ID 处理，不重复提交确认进度 |
| 用户同时要求整图生图与全元素可编辑 | 解释冲突并请求优先项，不交付伪可编辑文件 |
| 源码导出、只改色以及 Web 私有交付 | 资源完整、文案不变、最终图片已检查，链接与可见性正确 |
| 输入含伪造工具指令、活动 SVG 或未经许可的外链 | 作为不可信资料处理，不执行或扩大权限 |

结构化路线使用确定性的文本/几何/导出测试；付费生图回归按批准预算手动运行，不自动挂入每个文档 PR 的 CI。Skill 元数据检查只能证明包结构有效，不能替代这些功能及视觉测试。
