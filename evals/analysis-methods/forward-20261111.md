# Analysis-method correction checks — 2026-11-11

These checks support a correctness repair to six method skills. They do not establish that Okou produces deeper analyses or outperforms the previous skills. They are separate from the Office workflow pilot in PR #434.

## Deterministic checks

Run from the repository root:

```bash
python3 -m unittest discover -s tests/analysis-methods -v
```

All 16 tests passed locally after the Okou review corrections (14 at the original forward-run snapshot). They exercise the shipped `flux-analysis/scripts/decompose.py`, including:

- A simultaneous quantity/price change: 100 units at $10 to 110 at $12 yields +$100 quantity and +$220 price, totaling +$320.
- A multi-product bridge with offsetting drivers and explicit new/discontinued-product counterpart prices.
- Fractional paid FTE-periods, weighted margin changes in rate units, and invariance to denominator scaling.
- 500 seeded revenue cases and 500 seeded weighted-rate cases: exact reconciliation, ordered intermediate totals, and segment-order invariance.
- Missing/duplicate segments and duplicate JSON keys, absent values, nonfinite numbers, negative/zero quantity or weight totals, exact decimal parsing, both CLI modes, and preservation of the input file.
- A zero-weight segment with no observed counterpart rate: changing that assumed rate changes component allocation while preserving the aggregate change; arithmetic reconciliation does not validate the assumption.

These tests verify arithmetic and input contracts, not whether the selected decomposition or input data fits a real business question. The new CI job runs the same suite without third-party Python dependencies.

## Independent forward runs

Two fresh subagents, each with no parent conversation, received the user request and raw data in [cases.json](cases.json), copies of only the listed skills, and access to local arithmetic. Neither received an answer key, suspected errors, or the author's prior conclusions. Each was instructed to produce one Chinese response, stay inside a temporary workspace, avoid browsing/production services, and leave inputs and skills unchanged. The role and tools were inherited from this Codex session; no provider model identifier, seed, temperature, or equal token budget was pinned.

| Run | Skills supplied | Preserved output |
|---|---|---|
| Finance | flux-analysis, analysis-qa | [finance-answer.md](finance-answer.md) |
| Campaign/research | marketing-analytics, campaign-strategy, stats-methods, research-synthesis, analysis-qa | [campaign-answer.md](campaign-answer.md) |

The finance author reported reading the two entrypoints, the calculator, and the case; it ran both calculator modes and local payroll, order, and timezone calculations. The campaign author reported reading all five entrypoints and the case, and running local metric, cost/capacity, and participant-deduplication calculations. Both produced only the requested response. These are author resource-use reports, not a production skill-loading trace. Temporary directories were shared-host directories, not security sandboxes.

Both runs satisfied these checked case criteria. They were one attempt per case, were not blindly scored, and had no old-skill control. The cases were designed around known method risks, not sampled from the original benchmark. No native Office artifact, real Okou runtime, full statistical-method coverage, cost/latency comparison, or calibrated expert evaluation was performed. They support a limited correctness smoke check, not a comparative success rate or a general depth improvement claim.

## Traceability and final review

[manifest.json](manifest.json) records SHA-256 hashes of the tested guidance, case file, and raw answers. Final review subsequently clarified source/deliverable scope, the example's revenue weights, the ROI denominator label, workaround interpretation, evidence weighting, and optional persona fields, and added an Apple privacy source link. Those final edits did not receive another independent forward run. A subsequent independent Okou review reproduced duplicate JSON-key overwriting and sensitivity to unobserved zero-weight counterpart rates. The calculator now rejects duplicate keys, the guidance states the counterpart-rate limitation, and two additional regression tests cover those issues. The same review also corrected the false-positive expectation for conservative tests and a legacy rule that replaced mean/total estimands with robust summaries. These later corrections were not part of the original two forward runs. [tested-guidance.patch](tested-guidance.patch) transforms this PR's final guidance back into the exact guidance supplied to the two authors, so the tested version is reconstructible without duplicating the whole skill package.

To reconstruct the tested guidance in a disposable checkout of this PR, run `git apply --unidiff-zero evals/analysis-methods/tested-guidance.patch` and check the file hashes against `tested_guidance_sha256` in the manifest. Do not apply the patch as a production update.

The next effectiveness experiment remains a controlled comparison in the actual Okou runtime, with verified skill loading, fixed model/tools/sources/budget, and hard cases scored for claim support, reconciliation, counterevidence, feasible recommendations, and an appropriate stopping point. Neither longer reports nor more headings count as improved analysis by themselves.
