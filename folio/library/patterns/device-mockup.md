# Device mockup

> **Modified by Okou.** Adapted from Folio; [source and authorship](../INDEX.md#source-and-authorship).

**Use for:** Showing a real digital product in a recognisable screen context.

**Composition**
- Use one device as the hero, large enough for the relevant interface detail to be understood.
- Align its base with a colour-field edge or overlap that edge deliberately. A flat bezel often keeps attention on the product rather than the hardware.
- Use a second device only when it demonstrates a meaningful responsive variation.

**Asset and layout checks**
- Obtain an authorised screenshot at the intended viewport. Remove private data, notifications and account details before placement.
- Match the screenshot's aspect ratio to the screen opening; crop intentionally rather than stretching the interface.
- Show only work that can truthfully be attributed to the subject. Label conceptual screens or prototypes as such.
- If interface text becomes too small, add a separate enlarged detail instead of claiming the device view proves readability.

**Watch for:** Decorative hardware dwarfing the UI, distorted screens, misleading attribution, or fake functionality implied by a static image.

**Construction:** Place the screenshot within a simple screen mask and keep bezel geometry separate. No capture or mockup generator is required by this card; inspect the final composite at delivery size.
